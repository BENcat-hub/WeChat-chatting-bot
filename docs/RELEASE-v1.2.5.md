## 修复：发给「桃桃真可爱」的消息全落进「陈奥琦」，每条重复 3 次

### 真正的根因（不是焦点被抢，是名字匹配认错人）
`header_names_target()` 用 `contact_aliases` 里的旧备注做匹配：
- `contact_aliases` 里 `"桃桃真可爱": ["陈铭坚"]`（10-18 那次改备注留下的）
- `name_match("陈铭坚", "陈奥琦")` 走了「同长度 + 首字相同」的宽匹配，返回 **0.55**
- 宽匹配 >= `NAME_MATCH_LENIENT`，于是「陈奥琦」的聊天标题被判定为「桃桃真可爱」

结果：定位点到陈奥琦的行 → 身份闸（比对头部 OCR）也认为自己在桃桃窗口 → 文本敲进陈奥琦 →
WeFlow 在桃桃那边读不到 → `send_attempts=3` → 每条 3 份；再进重发队列就更多。

### 修法
1. `name_match()` 的宽匹配收紧为**首字与末字都相同**且长度 ≥3（`陈铭坚` vs `陈奥琦` 末字不同 → 0.0；
   `测试群` vs `测讠羊` 这种 OCR 形近仍由「学习到的别名」精确命中，实测不受影响）。
2. `header_names_target()`：第一个名称走原判定；**别名只接受整串相等或包含**，不再接受宽匹配。
3. `open_chat()` 行点击加 `row_click_cooldown_s`（默认 2.5s）：同一目标、同一落点的重复点击直接跳过，
   不再触发微信的「双击 → 会话弹成独立窗口」。

### 验证（真机）
- `header_names_target` 单测：`桃桃真可爱` vs `陈奥琦` → **False**；vs `陈铭坚`（真备注）→ True；
  vs `桃桃真可爱` → True；`测试群` vs `测讠羊` → True；`文件传输助手` 自身 → True。
- `open_chat("桃桃真可爱")` → 头部 OCR `桃 桃 真 可 爱`；`open_chat("陈奥琦")` → `陈 奥 琦`，不再串号。
- `send(..., commit=False)` dry-run：`桃桃真可爱` / `陈奥琦` / `文件传输助手` 三处身份校验均通过。

> 之前已经发出的重复消息仍无法通过 WeFlow 撤回（没有 revoke/recall 接口）。
