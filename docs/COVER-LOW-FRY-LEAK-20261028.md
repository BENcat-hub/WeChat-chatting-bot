|---|---|---|

## 2 根因

### 2.1 f0 提取器选错（低音跑音的主因）

`convert_vocals()` 原来把 `rmvpe`/`fcpe` 都映射成 `parselmouth`，但线上那次请求传的是
`harvest`，于是直接用了 pyworld 的 harvest。在 50-120 Hz 这一段 harvest 会整段翻倍：

| 提取器 | \|cents\| 中位 | >100c | 八度错误 | 低音区 >100c |
|---|---|---|---|---|
| harvest（线上） | 23 | 15.1% | 3.90% | **44.3%** |
| crepe | 19 | 12.0% | 4.06% | — |
| **parselmouth** | **16** | **7.3%** | **0.39%** | **≈19%（已到测量噪声底）** |

`_repair_f0_octaves` 救不了：它靠 9 帧中值做参考，而**整段低音都被翻倍时中值也是翻倍的**，
所以只改到 49/17689 帧。这就是「低音一唱就跑到高八度」的来源。

### 2.2 uv=0 的帧仍带非零 f0（气泡音变电音的机械原因）

`SynthesizerTrn.infer()` 里 uv 只进了 encoder，decoder 拿的是 `interpolate_f0()`
填过洞的 f0。`SourceModuleHnNSF.forward()` 的 docstring 明写「无音高帧 f0 应为 0」，
它按 `f0 > voiced_threshold` 决定正弦源，于是**气声/气泡音帧被强制灌进一条谐波**。
训练与推理都是这么干的（`preprocess_hubert_f0.py` 同样调 `interpolate_f0`），
所以模型学到的就是「气声也要有音高」。

### 2.3 `restore_timbre` 的「辅音移植」把原唱混回来了（去不干净 + 撕裂的主因）

```python
w  = wf * actf * CONS_RATIO            # CONS_RATIO = 0.6
sc = sc*(1-w) + sref*scale*w           # sref = 原唱频谱
scale = clip(body_rms_conv/body_rms_ref, 0.25, 4.0)
```

`w=0.6` 时已经把原唱的 6-16 kHz 以 0.6 的权重叠进来；`scale` 在成品比原唱响时会
**放大到 4×**，等效系数冲到 0.84。实测：

* 网络原始输出与原唱 7-12 k 波形相关 **−0.001**
* `restore_timbre` 之后 **+0.742**
* 成品里原唱波形系数 alpha **+0.752**，原唱贡献了成品 7-12 k 能量的 **56.8%**

两个歌手的齿音波形叠在同一频段，互拍频 → 用户听到的「撕裂」；同时原唱的音色信息
也一起进来了 → 「去不干净」。

顺带查过 Demucs：`htdemucs_ft` 比 `htdemucs` 只干净几个百分点，100-300 Hz 的原唱
残留 **0.137 → 0.127**，两边各频段差 <0.3 dB。**换模型救不了这件事**，所以没有去动
分离结果，也没有加「伴奏侧再掩一次」的后处理（那会在翻唱唱到哪就在哪压伴奏，能听出泵动）。

## 3 改了什么（`rvc-backend/server.py`）

备份：`rvc-backend/server.py.bak-20261028-f0cons`。`py_compile` 通过，
`lyric_lines / apply_vocal_gate / restore_timbre / match_dynamics / clean_vocal_output /
convert / resolve_audio / auto_key_shift / mix_and_export / convert_vocals` 全在。

1. **`_resolve_svc_f0(requested)` + `SVC_F0_METHOD`（默认 `parselmouth`）**
   请求什么提取器都先过这里。`BACKEND_SVC_F0=caller` 可以退回旧行为。
   日志：`f0 提取器: 请求 harvest → 使用 parselmouth（低音区八度错误 0.4% vs 3.9%）`。
2. **`_install_f0_uv_zero()` + `F0_ZERO_UV`（默认开）**
   运行期把 `SynthesizerTrn.infer` 换成一份字节级相同的副本，只改一行：
   `f0_dec = f0 * (uv > 0.5)`，decoder 拿到的无音高帧 f0 = 0。
   日志：`已启用「无音高帧 f0 清零」`。原始库文件不动，重装依赖也不冲突。
3. **`CONS_RATIO` 0.6 → 0.10，`scale` 上限 4.0 → 1.0，并且只在原唱「无音高」的帧移植**
   用 parselmouth 对原唱做 `voicing_threshold=0.6 / 53-900 Hz` 判定，取 `uv_w`
   乘进权重，实测只覆盖 **52%** 的帧（真正是辅音的帧）。
   日志：`辅音移植: 仅 52% 的帧（原唱无音高）`。既有咬字瞬态，又不再复制原唱的音高段。
4. **`TIMBRE_DYN` 在 `wide` 预设里恢复为关**（我今天一度打开过，实测是错的）
   同一份 converted 只改这一个开关：
   `dyn0 → 混音 4-6k +2.4 / 6-9k −2.0 / 9-12k +2.1 dB`（相对母带，与旧成品一致）
   `dyn1 → 混音 4-6k +5.0 / 6-9k +1.5 / 9-12k +6.8 dB`（整体发亮发毛）
   它按逐帧能量比调增益，响的帧顶到 +6、静的帧压到 −10，净效果是**高频扩展器**，
   不是电平匹配器。所以只留 `BACKEND_TIMBRE_DYN=1` 给手动 A/B。
5. **分离模型换 `htdemucs_ft`，缓存目录带标签**
   `DEMUCS_MODEL`（默认 `htdemucs_ft`）、`DEMUCS_SHIFTS=1`、`DEMUCS_OVERLAP=0.5`，
   缓存路径 `<song_sha>-<DEMUCS_TAG>`，例：`...-htdemucs_fts1o05`。旧缓存不再复用。
6. **缓存 fx 串扩写**，任何一项配置变了都不会再返回旧 mp3：
   `...sf{SVC_F0_METHOD}z{0/1}cr{CONS_RATIO}td{TIMBRE_DYN_CLIP_DB}sep{DEMUCS_TAG}`。

* 音高提取器退回旧行为：`BACKEND_SVC_F0=harvest`（《落叶归根》那版的手感）或
  `BACKEND_SVC_F0=caller`（完全听调用方，只把 parselmouth 换掉）

## 8 第二轮（10-28 下午）：主歌电音 + 副歌「我听见了你的声音」掉调/破音

用户原话：「主歌电音太多，可能是薛之谦的音色比较难采样，副歌第一句『我听见了你的
声音』本该在第五组，但是莫名其妙降调了，降到快三组的位置，而且破音」。
随后补充「比最开始那版主歌好太多，副歌也不错，但还是存在刚刚说的问题，不要考虑成本修复」
和「也可能是薛之谦原曲加的混响太多干扰了采样」。

### 8.1 副歌整句掉调的根因：f0 提取器锁在**次谐波**上，不是模型唱错

第一遍副歌时长音（84.5-87.5 s）在母带里的真实音高是 **349 Hz**（F4），+8 半音后应为
**554 Hz**（C#5，第五组）——与用户「本该在第五组」的判断一致。第二遍同句（175.4-183.5 s）
成品落在 554.1 Hz，第一遍旧成品却落在 431 Hz（其中 216 Hz 是 84 s 之前那半句）。

判定 349 而非 175 的两条硬证据：

1. **谐波结构**：85.0 s 的峰是 `175@-3  350@0  700@-13  1044@-12`（dB re max）。
   350 / 700 / 1050 是完整的一串（1、2、3 次谐波），而 525（175 的 3 次）、875（175 的 5 次）
   **完全缺失**。一个元音在 3 秒里连续挖掉奇次谐波、只留偶次谐波，物理上不可能；
   反过来，「f0=349 的声源 + 175 Hz 的伴奏渗漏」就完全解释得通。
2. **两遍同句对照**：谱图上两遍的旋律轮廓一致（都是先下行到 230 附近再拉长音），
   长音段第一遍在 349、第二遍也在 349；用 175 去解释第一遍，就和第二遍差了一个八度，
   而同一首歌同一句词不会差八度。

而 **harvest 在 81-89 s 给出的是 216 Hz**（不是 175 的整数倍关系，是直接把整句锁到了
别的音上）；parselmouth 给 174.6 Hz（干净地锁在 1/2 次谐波）。两个都不对。
因此用户对 parselmouth 那版的否决（「不要再用parselmouth」）和这次「掉调」是同一类问题
的两个方向，不能靠互相切换解决。

### 8.3 「主歌电音」

客观代理（`_diag1028/buzz_mod.py`，1-4 kHz 包络的调制谱）：40-60 Hz 调制占比
原唱 3.6% → 旧成品 7.8% → 新成品 5.4%；活动门本身只贡献 0.3 个点（旧链路里是
「门 → 强弱 → 清理」三级都在加，现在只剩门）。主歌逐帧 f0 抖动成品 10.9 音分
（原唱 12.4），谱平坦度 0.650（原唱 0.628）——不是「抖动/喷麦」型电音。

剩下的电音是音色模型的固有成分（孙燕姿模型唱男声 +8 半音，共振峰被整体上移），
不是参数能消掉的；能动的只有 `BACKEND_CLUSTER_RATIO`（0.30）和 `noise_scale`（0.20），
后者实测从 0.20 扫到 0.50 时输出 HNR 稳定在 19 dB 左右、纹丝不动，不要再用它追电音。

### 8.4 破音

成品没有数字削波：峰值 0.823，≥0.999 的样点 0 个；20 ms 包络 |Δ| 的 p99 是 6.79 dB，

## 9 第三轮：主歌「破音 + 来回震荡」查到的三个真凶

用户逐句点名：`若美丽的故事来的太晚`、`就好像你存在…` 的「你」、`袖手旁观着别人` 的「观」、
副歌 `我听见了你的声音` 的「你的声音」。频谱上把用户点名的位置全画了一遍
（`_diag1028/stems_spec.py`、`verse_osc.py`、`crack_zoom.py`），再逐级量 10ms 包络突跳，
定位到三处**结构性**问题（都不是音高提取器的问题了）：

### 9.1 分块接缝正好压在用户点名的那几句上

`convert_vocals` 每 20 秒切一块，块间 1 秒等功率交叉淡化。接缝两边是**两次独立推理**：
`SineGen._f02sine` 里 `rand_ini = torch.rand(...)` 每次随机初相，噪声也是随机采的。
两轨在长音上加权混合 = 互相抵消 + 拍频，听感就是「破音 + 来回震荡」。

用户点名的三句正好卡在接缝上（接缝 20/40/60/80s，交叉淡化占 1 秒）：

| 用户点名 | LRC 时间 | 接缝 |
|---|---|---|
| 若美丽的故事来的太晚 | 41.34 起 | 40-41s（正压句首） |
| 就好像你存在… | 56.58-64.32 | 60-61s（句内） |
| 我听见了你的声音 | 81.03 起 | 80-81s（正压句首） |

改法（`_chunk_bounds`）：把每个接缝在 ±4 秒内挪到「1 秒交叉窗口平均能量最低」的位置
（前奏/间奏/气口），最多挪 4 秒。实测接缝落点与窗口能量：

```
16.0s -92.8 dB | 40.2s -79.8 dB | 63.5s -66.8 dB | 79.0s -84.3 dB
103.0s -81.4 dB | 116.8s -91.5 dB | 140.8s -57.3 dB | 156.0s -73.4 dB
```

整首歌人声峰值约 -15 dB，接缝处比它低 40-75 dB，交叉淡化等于在静音里做，听不出来了。
`BACKEND_CHUNK_SNAP=0` 可关。

### 9.2 无音高帧的噪声激励是 10 倍跳变

`SourceModuleHnNSF` 里 `noise_amp = uv*noise_std + (1-uv)*sine_amp/3`，即 uv=0 时的噪声
是 uv=1 时的 **10 倍**（0.033 vs 0.003）。我在 8.5 里按 uv 清零 f0，于是句子中间任何
50-200ms 的气口都会变成「正弦突然消失 + 噪声突然放大」。用户点名的位置正好有：

```
72.56s 洞 46ms（原唱 pyin 也无声）
83.73s 洞 197ms（原唱也无声）
```

改法（`_close_uv_holes`）：把 uv 里**短于 200ms** 的洞补成有声再进解码器，长气声/气泡音
仍保留噪声激励。实测音节内部 ≤80ms 的洞整首 105 个，这一改直接消掉。

### 9.3 去齿音是逐帧硬判，增益在 1.0 和 0.65 之间翻

`clean_vocal_output` 原来是 `over = be > thr` 然后逐帧乘 `clip(thr/be, 0.65, 1)`，
hop=256（5.8ms）。`be` 在阈值上下抖动时，增益每帧翻一次，等于在齿音上叠一个
170Hz、3.7dB 的方波——这就是「破音/电音」的一个直接来源。
改成带攻放的一极点平滑（下压 3ms、恢复 80ms）。

### 9.4 改完剩下的

逐级量 10ms 包络突跳（只统计高于 -40dB 的可听帧，p99.5）：

| 段落 | 原唱 | 改前 | 改后 |
|---|---|---|---|
| 若美丽的故事 | 13.1 | 15.2 | 14.7 |
| 就好像你存在 | 11.8 | 13.7 | 16.2 |
| 袖手旁观着别人 | 9.9 | 13.4 | 13.3 |
| 我听见了你的声音 | 9.3 | 10.5 | **9.7** |
| 第二遍副歌 | 13.3 | 12.2 | **11.6** |

**注意这条指标不进人耳**：`converted.wav`（刚出网络的干声）就已经比原唱高 2-4 dB，
后处理只贡献零点几 dB——剩下的是 SVC 合成本身的抖动，不是链条能压掉的。
接缝改完副歌已经回到原唱水平；如果「就好像你存在」那句还毛，下一步该换的是
目标音色模型（孙燕姿唱男声 +8 半音的固有失真），不是继续调后处理。

改完的开关：`BACKEND_F0_SHAPE=0`（关 f0 塑形）、`BACKEND_CHUNK_SNAP=0`（关接缝挪位）、
`BACKEND_F0_ZERO_UV=0`（关无音高帧清零，同时也就关掉 9.2 的补洞）。
新成品：`rvc-backend/output/7ba30692d6601d4a-dcd156a1.mp3`，
`fx=...sffcpez1cr0.10...ofs10.60ds2uvcsm1`。
