## 修复：同一条消息连发多份（发给 A 的消息落进了 B 的会话）

### 现象
2026-10-23 早上，本该发给「桃桃真可爱」的消息，在「陈奥琦」的会话里每条出现 3 次（`早`、`又在纠结早饭吃什么`、`想半天还是馋你昨天那个蟹黄拌饭？` 各 3 条）。前一晚同一机制造成「卷子分完了没」连发 9 条。

### 根因
1. 校验会话身份、粘贴文本、按回车是三段独立的合成输入。用户当时正在陈奥琦窗口里打字，**校验那一刻前台还是桃桃，Ctrl+V 的时候已经换成陈奥琦** → 文本敲进了别人的会话。
2. WeFlow 在目标会话里读不到这条消息 → 判定「没送到」→ 按 `send_attempts=3` 重试 → 每次都重复上面的错位 → 3 份；失败再进重发队列 → 更多份。

### 修法（`scripts/wxui.py`）
- 新增 `_identity_recheck(cfg, target)`：**保守判定**——只有连续两次都读到「一个像人名的会话名，且与目标相似度 < 0.3」才否决；OCR 读不出或读到界面噪声一律放行（第一版太严，把正常发送全拦住了）。
- 粘贴之后、回车之前调用它；认错会话就 `Ctrl+A` + `Backspace` 清空输入框，不回车上屏，标记 `no_requeue`。
- 回读验证失败时再调一次：如果确认已经敲进了别的会话，**直接放弃重试**（`sent into a different chat; not retrying to avoid duplicate delivery`），把「3 份」压回「1 份」。
- `wxui_sender.py` 尊重 `no_requeue`，这类失败不再进重发队列。
- 新增配置 `defer_to_human`（默认 **false**）：打开后，检测到用户正在用键盘/鼠标就让路不发送。注意打开后你在用电脑时机器人会一直等，所以默认关闭。
- `identity_recheck_before_enter`（默认 true）控制上面两道闸。

### 验证
- 连续 3 条自发消息到「文件传输助手」：`localId=308/309/310`，每条只 1 份、回读确认到位。
- 旧版行为复现依据：`bridge.log` 里 08:42:31 / 08:43:50 / 08:45:08 三条 `未能验证送达 桃桃真可爱 | 尝试=3`，而对应文本 3 份全部落在陈奥琦会话（`localId=395..403`）。

> 已发出的重复消息无法通过 WeFlow 撤回（没有 revoke/recall 接口），需要手动删。
