# 梗百科 · astrbot_plugin_memewiki

<p align="center"><img src="logo.png" width="180" alt="梗百科"></p>

> 让 Bot 认得群里的梗和黑话：先查内置词库（毫秒级），查不到再回落 [cnmeme.wiki](https://cnmeme.wiki) 公开接口；
> 支持 `/梗` 图片卡片、`/黑话` 自建词条，以及面板里的可视化编辑页。

**装完即用**：插件自带 **6668 条**词条数据库（`data/memes.db`，约 16MB），不需要先抓数据、不需要联网。

## 为什么需要它

大模型对**新梗、群内黑话、缩写**经常硬猜，或者干脆答"我不知道"。
直接联网搜索又慢又不准（1–2 秒，还常搜到无关内容）。

这个插件做三件事：

1. **内置词库优先**：6668 条词条随插件分发，查词 **1–3ms**（SQLite 精确匹配），比走在线 API 快约 1000 倍。
2. **自动查梗**：消息像梗查询时（裸词、「XX 是什么梗」等），在请求发给模型前先查好并注入上下文，不依赖模型自觉。
3. **先接梗再解释**：注入内容把「怎么用 / 怎么接」放在最前面，模型优先照着用法回一句，而不是上来讲典故。

## 功能

| 功能 | 说明 |
|---|---|
| `/梗 <词>` | 查梗，默认返回**图片卡片**（配置里是下拉选项：图片卡片 / 纯文字） |
| `/黑话 <名称> <含义>` | 记一条群内自造黑话，独立于内置词库保存 |
| `/黑话 列表` / `/黑话 删除 <名称>` | 查看 / 删除（删除仅管理员） |
| LLM 工具 `search_meme_wiki` | 模型可主动调用查梗 |
| 自动预查 | 先查本地（毫秒级），只有真在问梗或像词条的短词才联网；同一个词 10 分钟只搜一次 |
| 检索存档 | 查到的梗留档在本地小库（`search_archive.db`），同一个词下次直接用：不联网、不花判定时间；查不到的词也会记几天负缓存 |
| 面板编辑页 | 插件页「自定义黑话」，可视化增删改 |
| 可选自动更新 | 每天定时抓取新增词条并重建词库（默认关闭） |

## 安装

**方式一：插件市场**（推荐）
AstrBot WebUI → 插件市场 → 搜索「梗百科」→ 安装。

**方式二：手动**
把本仓库放进 `data/plugins/astrbot_plugin_memewiki/`，重载插件或重启 AstrBot。

依赖：`aiohttp`、`Pillow`（AstrBot 自带），无需额外安装。

## ✅ 装完就能用：内置用法说明

**不需要改人设。** 插件每次请求都会附带一小段内置规则（约 150 token）：

```text
1. 看到没有十足把握的网络新词、梗、缩写、黑话，先调 search_meme_wiki 查，别硬猜别编
2. 查到之后先接梗、别科普：照着词条里的【怎么用/怎么接】用一句，像本来就会
3. 只有对方明确问「这是什么梗」才解释出处，一两句就够
4. 查不到就说不知道，不要把两个不相干的梗拼一起
5. 说话用短句，别用「首先/其次/希望对你有帮助」这类客服腔
```

这段规则由插件注入，不写进你的历史、不占用人设。想关掉或换成自己的，改配置项：

| 配置 | 默认 | 说明 |
|---|---|---|
| `inject_guidance` | `true` | 关掉后完全靠你自己的提示词 |
| `guidance_text` | 空 | 填了就整段替换内置文案 |

> 只想要「/梗 词条查询」功能的，把 `inject_guidance` 关掉即可，指令照常可用。

## 🔍 词库没收录时：借用 AstrBot 的搜索

内置词库是快照，新梗总会漏。查不到时不再装懂，按下面顺序兜底：

1. **用 AstrBot 已配好的网页搜索**（控制台 → 配置 → 网页搜索：总开关 + 服务商 + Key；deepseek / baidu / tavily / serpapi / brave / bocha / exa / firecrawl / anysearch 都支持）
2. 搜不到、超时或调用失败 → 让模型说「不知道」或反问「这什么梗」，**绝不硬解释**

> 插件**不存任何 API Key，也没有自己的搜索源**。没在 AstrBot 里配搜索，就只是不联网查，本地词库照常工作。

| 配置 | 默认 | 说明 |
|---|---|---|
| `search_mode` | `auto` | 一个下拉管到底：`auto` 插件先代搜，搜不到再提示模型自己搜（推荐）；`plugin` 只插件代搜，搜不到就当没查到；`model` 只提示模型自己搜；`off` 完全关闭，既不代搜也不提示 |
| `search_max_chars` | `10` | 不是明确问梗时，只有 ≤ 这个字数的短词才会进入闸门判定 |
| `gate_mode` | `llm` | 联网前的闸门（下拉选项）：`llm` 规则 + 模型判定（推荐）/ `rules` 只用规则（零延迟、零成本）/ `off` 关闭闸门（等同旧行为） |
| `gate_provider_id` | 空 | 闸门判定用哪个 provider；留空 = 用当前对话模型 |
| `gate_timeout` | `1.2` | 闸门判定超时（秒）：超时就按「查」放行，不拖慢回复 |
| `gate_cache_ttl` | `600` | 闸门判定结果缓存多久（秒） |
| `search_timeout` | `6.0` | 搜索超时（秒），超时按「没查到」处理 |

**聊天内开关**：`/网搜 auto`（推荐）、`/网搜 plugin`（只代搜）、`/网搜 model`（只提醒模型）、`/网搜 off`、`/网搜 状态`。
状态存在 `data/plugin_data/astrbot_plugin_memewiki/settings.json`，重启不丢；聊天里设置过就优先于上面的配置项。

## ⚡ 什么时候才联网：预查闸门

"词库没收录就联网"听起来合理，实测很浪费：群里 **78% 的"梗查询"其实是闲聊整句**（「我是谁」「情绪」「你今天怎么样」），每次白花 0.4–1.4 秒和 900 字上下文。

所以预查分三步：

1. **先查本地**：群内梗 → 自定义黑话 → 内置词典，实测 **0.1–0.9ms**。命中就直接注入，不联网、不花钱
2. **本地没有，过闸门**：
   - **规则层（0 延迟）**——明确在问梗（什么梗 / 啥意思 / 啥是 / 出处 / 谐音 / 缩写…）直接放行；请求类（找本子 / 发图 / 点歌 / 评价）、游戏机制与数值、指代（这个 / 右边）、疑问整句、口头禅（666 / 好的 / 去了）直接拦下
   - **模型层（约 0.65 秒）**——「像词但不确定是不是梗」的（`杂鱼` vs `妈妈`）交给一次判定，返回 `{"term","lookup"}`；提示词要求「1–4 字的陌生专有词 / 绰号优先当作梗」，所以 `僵尸`、`唐诗`、`马眼` 这类裸词不会被漏掉
   - **判定和联网同时开始跑**：说「不查」就取消请求，说「查」就直接用同一个请求 —— 该查的时候延迟不变，不该查的少等
   - 判定超时 / 出错 / 没配模型时**一律放行**，宁可多查一次也不误杀
3. **同一个词 10 分钟内只搜一次**：搜到过的结果直接复用；重复词折叠后共用缓存（`杂鱼杂鱼` → `杂鱼`、`666666` → `666`、`已取餐已取餐` → `已取餐`）。cnmeme 预查超过 3 秒会静默跳过，不会把内部超时信息发给用户
4. **注入的搜索结果会摊平**：provider 返回的 JSON 会被转成「1. 标题 —— 摘要」最多 5 行，去掉 HTML / markdown 记号后再截到 900 字——以前是直接截半截 JSON，既费上下文又常被截在字符串中间

> 线上 48 小时实测：137 次联网里只有 31% 是该查的梗。加上闸门后，93 条标注意料上的**精准率 31% → 78.8%**、**召回率 89.7%**，噪声从 64 条降到 7 条。

实测同一串 8 条消息（杂鱼 / 杂鱼杂鱼 / 杂鱼杂鱼杂鱼 / 666 / 666666 / 不是你自己发的 / 这杂鱼是你说的 / 已取餐）：

| 消息 | 结果 | 联网 |
|---|---|---|
| 杂鱼 | 搜索兜底命中 | 1 次 |
| 杂鱼杂鱼 / 杂鱼杂鱼杂鱼 | 复用缓存 | 0 |
| 666 | 搜索兜底命中 | 1 次 |
| 666666 | 复用缓存 | 0 |
| 不是你自己发的 / 这杂鱼是你说的 | 闸门挡掉 | 0 |
| 已取餐 | 搜索兜底命中 | 1 次 |

**联网 8 次 → 3 次。**

想看插件当前判断了什么，日志里会写清楚：

```text
[memewiki] 预查命中并注入: 马头 (679 字, 本地 3ms)
[memewiki] 预查未命中且不像梗，跳过联网: 这么会（3 字）
[memewiki] 命中搜索缓存: 杂鱼（还剩 599s，0ms）
```

> 被闸门挡掉的整句不会注入任何资料拍脑袋猜。如果你希望模型自己去搜这类句子，用 `/网搜` 切到让它自己搜的模式，或者把短句补进 `/黑话`。

### 想效果更好（可选）

内置规则管的是行为，语气仍然来自你的人格。如果 bot 本来就很"客服腔"，
在人格里补一句会更自然：

```text
遇到不确定的梗先查 search_meme_wiki，查到就用它接一句，别解释。
```

### 三种情况根本不联网

1. **本地命中**（10ms 级精确查）
2. **检索存档命中**：这个词以前查过，结果缓存 90 天，重复玩同一个梗不再搜
3. **闸门拦下**：整句闲聊、口头禅、请求、游戏数值这类结构上就不是词条

只有「短、像词、但不认识」的消息才会走到联网那一步。

## 词库更新（可选）

内置词库是**发布时的快照**。想跟进新梗，两种方式：

| 方式 | 说明 |
|---|---|
| 面板开「每天自动同步」 | 到点自动增量抓取 + 重建词库（默认关闭） |
| 手动跑一次 | 在插件目录执行 `python scripts/sync_memes.py` |

```bash
cd data/plugins/astrbot_plugin_memewiki
python scripts/sync_memes.py
```

- **只补新增**：列表按 `updated_at` 倒序翻页，翻到「整页都没变化」就提前停止（稳态 1 页 / 约 1.4 秒；从零全量 223 页 / 5 分钟）
- **详情分批**：每次最多补 1000 条详情（`sync_detail_limit`），没补完的排进下一次，约 1.15 秒/条；列表里的标题/摘要会先兜底，所以词库立即可用
- 中途 Ctrl-C 不会损坏数据，重跑继续
- 分页中断、空页或新列表异常变少时会拒绝更新；新数据库先写临时文件并做完整性检查，条数少于旧库也不会覆盖
- 运行时会比较同步库与插件随包快照，自动使用词条更多的完整版本
- 产物写到 `data/plugin_data/astrbot_plugin_memewiki/`：`memes.db` + `index.json` + `details/`
- 从零全量抓约 6668 条、默认串行限速 0.35 秒/次，需要 2 小时左右（一般用不到，内置库已包含）
- 中途断了重跑就行：加 `--reuse-items` 复用已抓到的列表，只补缺的详情

## 配置

| 配置项 | 默认 | 说明 |
|---|---|---|
| `reply_mode` | `image` | `/梗` 的回复形式（下拉选项）：图片卡片 / 纯文字 |
| `search_mode` | `auto` | 词库没收录时怎么联网（下拉选项）：自动 / 只插件代搜 / 只提示模型自己搜 / 完全关闭 |
| `search_max_chars` | `10` | 不是明确问梗时，只有 ≤ 这个字数的短词才联网（挡掉闲聊整句） |
| `search_timeout` | `6.0` | 搜索超时（秒），超时按「没查到」处理 |
| `inject_guidance` | `true` | 是否注入内置的接梗规则（关掉完全靠你自己的人设） |
| `guidance_text` | 空 | 填了就整段替换内置规则文案 |
| `auto_sync_enable` | `false` | 每天自动同步词库 |
| `auto_sync_hour` | `4` | 同步时刻（0–23 点，默认凌晨 4:00） |
| `sync_detail_limit` | `1000` | 每次同步最多补抓多少条详情（约 20 分钟）；没补完的自动排到下一次 |
| `archive_enable` | `true` | 检索存档：查到的结果留档，同一个词下次直接用 |
| `archive_ttl_days` | `90` | 查到结果的存档有效期（天），0 = 永不过期 |
| `archive_miss_ttl_days` | `3` | 查不到的负缓存有效期（天），期间同词不再联网 |
| `inject_deadline` | `6.0` | 预查超过这么多秒才拿到结果就丢弃、不注入上下文（回复早发出去了） |

## 数据存放位置

所有**用户数据与运行时缓存**都写在 AstrBot 规范位置，不写插件目录：

```
data/plugin_data/astrbot_plugin_memewiki/
├── user_terms.json      你加的自定义黑话（含 .bak 备份）
├── group_slang.json     可选：自带一份「词 → 含义」的 JSON 词表（不随插件分发）
├── memes.db             同步后的词库（可选，同步过才有）
├── index.json           抓取产生的标题索引
├── items.json           列表快照（重建 SQLite 时用，约 6MB）
├── search_archive.db    检索存档（查过的梗 + 复用次数 + 负缓存，独立小库）
└── details/             抓取产生的词条详情缓存
```

`group_slang.json` 是可选的私货入口：想批量导入一批群内黑话，放一个 `{"词": "含义"}` 的 JSON 到上面这个目录即可（不用重启，重载插件后生效）；日常加词用 `/黑话` 或面板编辑页就够了。

插件包内自带的 `data/memes.db` 是**只读快照**，运行时以只读方式打开，不会被改写。
升级插件不会影响上面这些数据；**卸载插件**才会连同 `plugin_data` 目录一起删除，重装前备份 `user_terms.json` 即可。

## 数据来源

词条内容来自 [cnmeme.wiki](https://cnmeme.wiki) 的公开只读 API：

- `GET /api/v1/public/memes?q=&limit=&offset=` 搜索 / 列表
- `GET /api/v1/public/memes/{slug}` 详情

本插件只做本地缓存与检索：词条版权归 cnmeme.wiki 及原作者，界面上保留了来源链接。
自行更新词库时请遵守站点规则：限速（脚本默认 0.35 秒/次）、429 退避。

## 常见问题

**Q：`/梗` 提示"词库里没有收录"？**
A：内置词库没有、wiki 也没收录。群内自造词用 `/黑话` 加；想补 wiki 新词就跑一次 `scripts/sync_memes.py`。

**Q：升级插件会丢我的黑话吗？**
A：不会。黑话在 `data/plugin_data/astrbot_plugin_memewiki/user_terms.json`，升级不碰这个目录；卸载时只要确认框里的「同时删除数据」不勾（默认不勾），重装后黑话照样在。真要图稳，先备份 `user_terms.json`。

**Q：`memes.db` 会被同步覆盖吗？**
A：同步只写 `plugin_data` 里的副本，插件包内的只读快照不会被改动。1.5.3 起，分页不完整、新列表变少、数据库完整性检查失败或新库条数少于旧库时都会拒绝覆盖；运行时还会在同步库和随包快照中自动选择词条更多的一份。

**Q：Windows 上更新插件报 `WinError 32 另一个程序正在使用此文件`，升不到 1.5.2？**
A：这是 **1.5.1 及更早版本**的毛病：插件把 `memes.db` 的只读连接一直攥在手里（`self._db_conn` 常驻），而 AstrBot 更新插件的顺序是「**先**删插件目录 → 再解压新包 → **最后**才调 `terminate()`」，删目录那一步被自己的句柄挡住就报 WinError 32。1.5.2 已改成每次查询开连接、用完立刻关，插件任何时刻不再持有句柄。

老版本升级前，先让插件把句柄放掉，三种办法任选：

1. **禁用后再更新（最省事）**：面板 → 插件 → 把梗百科的启用开关关掉 → 等状态变「未启用」→ 点卡片上的橙色版本号「更新到 1.5.2」→ 更新完再点回启用。
2. **卸载再重装**：面板卸载（确认框里「同时删除配置」「同时删除数据」**默认都不勾，保持不勾**）→ 市场里重新安装。配置和 `plugin_data` 都在插件目录外面，黑话、设置不会丢。
3. **手动兜底**（已经更新失败过、插件目录被删了半截的情况）：停掉 AstrBot → 删掉 `data/plugins/astrbot_plugin_memewiki` 整个目录（进程退出了，Windows 也删得掉）→ 启动 AstrBot，再去市场安装；或在启动前直接把新包解压进去。

Linux / macOS 不存在这个问题，直接更新即可。

⚠️ 第 1 条的禁用状态会记进 `data/shared_preferences.json` 的 `inactivated_plugins`，更新完**记得把开关点回启用**，否则插件是「装好了但没在跑」。

**Q：卡片中文显示成方框？**
A：系统缺中文字体。插件会依次找 Noto CJK / 文泉驿 / 微软雅黑 / 苹方，都没有就退回 PIL 默认字体（中文变方框）。装任一中文字体即可。
