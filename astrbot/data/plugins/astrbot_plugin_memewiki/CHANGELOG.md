# CHANGELOG

## 1.6.0 — 2026-10-28

**同步改造 + 检索存档 + 三处闸门修正 + 搜索结果可读化。**

### 一、词库同步：从「每次都全量」改成「增量 + 早停」

线上词库卡在 6668 条很久不动，根因是个死循环：10-27 那次列表接口 503，`items.json` 只落了 2760 条，
而 `memes.db` 是 6668 条（含历史全量）；list 阶段用「本地条数 > 线上条数」判异常，于是每次都在 offset≈2760 中止 ——
列表永远补不齐，下一次列表又永远不完整。旧脚本还要把所有详情重抓一遍（实测 4389 秒），就算不被 503 打断也跑不完。

- 列表按 `updated_at` 倒序翻页，**翻到「整页都没变化」就提前停止**：稳态 1 页 / 1.4 秒，全量仍是 223 页 / 5 分 15 秒
- 参数：`--full` 全量、`--list-only` 只更新列表、`--limit N` 详情上限、`--max-pages N`、`--reuse-items` 复用已抓列表
- `pack_data.py` 不再跳过「没抓到详情」的条目，用列表里的标题/标签/摘要兜底 —— 这样增量才可能收敛
- 新配置 `sync_detail_limit`（默认 1000）：每次最多补 1000 条详情，没补完的排进下一次（约 1.15 秒/条）
- 实测：临时目录全量重建 28.6 秒（旧实现 4389 秒）；修复性全量 25 分 47 秒跑完 6678 条、db 9.3 MB，剩余 3102 条详情交给每日 04:00 慢慢补

### 二、检索存档：查过一次的梗，下次直接复用

新增独立小库 `search_archive.db`（放插件数据目录，**不塞进 `memes.db`**，免得被词库重建覆盖）：

- 查到结果后留档；同一个词再来先查存档，命中直接注入，**不联网、不调模型判定**
- 查不到的词也记负缓存（`archive_miss_ttl_days`，默认 3 天），避免同一个生词反复触发搜索
- 正缓存默认 90 天（`archive_ttl_days`，0 = 永不过期），`hits` 记录复用次数
- 查找顺序：本地精确查（10ms）→ 检索存档 → 闸门 → 联网。存档只做精确词复用，模糊匹配仍交给本地索引（实测短词路径用长文本撞相似度更差）
- 可整体关闭（`archive_enable`）

### 三、三处闸门修正（都来自线上日志）

1. **意图词不再整句直通**：以前只要包含「什么意思」就联网，于是「什么意思没看懂」白算 1.2 秒。改成整句超过 6 字且没有引号括住词时交给模型层；同时新增词形判断，「阿一古是什么意思」这种「词 + 问法」仍然直接查
2. **过期结果丢弃**：预查耗时超过 `inject_deadline`（默认 6 秒）就不注入 —— 线上出现过 22 秒后才补注入、回复早已发出
3. **群内黑话兜底**：闸门想拦、但 `user_terms.json` 里确实有这个群的黑话时，仍用黑话回答，不联网

自测：存档 24 项 + 修正 14 项 = 38 项全过；线上热重载后词库 6678 条、黑话 6 条、0 ERROR。

### 四、联网搜索结果可读化

搜索 provider（DeepSeek / Tavily / Bocha / Brave …）返回的多半是 `{"results":[{title,url,snippet}]}`。
以前直接把 JSON 截到 900 字注入——既费 token（同一批信息摊成 JSON 要占两三倍），又常常截在字符串中间，
留下半截 `{"results": [{"title": "垂钓中最烦的“四大...`。现在先摊平再截断：

- 解析成「1. 标题 —— 摘要」最多 5 条，去 HTML / markdown 记号、压空白、单条摘要限 90 字
- 解析不了（真被截断、不是 JSON、provider 换格式）时用正则从残片里抠 `title` / `snippet`，仍然给出可读几行
- 有 `answer` 之类没有 `results` 的结构，退回原样截断，不会把内容弄丢
- 单测 12 项（`test_humanize.py`）：完整 JSON、截断 JSON、纯文本、空串、`None`、无 results、HTML 噪声、长度上限

实测：`杂鱼` 的搜索结果原本是 900 字 JSON（还带 `\n` 转义与 url），现在是 5 行「标题 —— 摘要」，读起来省一半以上。

## 1.5.4 — 2026-10-28

**联网前加一道闸门：规则先砍，剩下交给模型判一次；判定和联网并发跑。**

线上 48 小时真实日志：预查触发 441 次、其中 137 次真的联网，人工标注后只有 **31%** 是「该查的梗」。
其余是「妈妈」「去了」「好的」这类口头禅、「如何评价华为车系」这类整句、「姆巴佩几号球衣」「速猪是哪八张卡」这类现实与游戏问题——
每次白等约 1 秒，还可能把不相干的词条当资料塞进上下文。

- **规则层（0 延迟、0 成本）**：明确在问梗（新增「啥是 / 是啥」）直接放行；找本子 / 发图 / 点歌 / 评价这类请求、游戏机制与数值、指代（这个 / 右边）、疑问整句、日常口头禅直接拦。在 64 条噪声上拦下 22 条、**误杀 0**
- **模型层（约 0.65 秒）**：短词但不确定是不是梗（「杂鱼」vs「妈妈」）交给一次 LLM 判定，只输出 `{"term","lookup"}`；提示词明确「1–4 字的陌生专有词 / 绰号优先当作梗」，专门救「僵尸」「唐诗」「马眼」这类裸词
- **投机并发**：模型判定的同时联网请求已经在跑；判定说「不查」就取消请求并写负缓存，说「查」就直接等同一个请求 —— **该查的延迟不变**（仍约 1 秒），不该查的从约 1 秒降到约 0.65 秒
- 判定超时 / 出错 / 没有可用 provider 时一律**按放行处理**：宁可多查一次，也不误杀真梗
- 新配置：`gate_mode`（`llm` / `rules` / `off`，默认 `llm`）、`gate_provider_id`（默认空 = 用当前对话模型）、`gate_timeout`（默认 1.2 秒）、`gate_cache_ttl`（默认 600 秒）
- 预查日志拆成「闸门拦下（规则）/拦下（LLM）/预查命中/注入上下文」几种，便于继续统计

实测（93 条已标注意料离线回放，真实 provider）：放行 33 条里 26 条是真梗，拦下 60 条里 57 条正确 ——
精准率 **31% → 78.8%**、召回率 **89.7%**；噪声 64 条降到 7 条，真梗只丢 3 条（「已取餐」「操你冯」「啊是奶奶奥利奥」）。
接线自测（三态判定、取消语义、`rules` / `off` 模式、守门人超时）28 项全绿。

## 1.5.2 — 2026-10-26

**修：Windows 上更新插件报 `WinError 32 另一个程序正在使用此文件`。**

- `memes.db` 以前在插件加载那一刻就打开、连接一直缓存在进程里；而 AstrBot 更新插件是「先删旧插件目录 → 再解压覆盖 → 最后才 reload」，reload 里才会调 `terminate()`。Windows 上文件被占用就删不掉也写不进，更新直接失败（Linux 不受影响，所以一直没发现）
- 现在改成**每次查询开一个只读连接、用完立刻 close**：插件任何时刻都不持有 `memes.db` 句柄，更新/重装/删除插件都不会再撞锁。（启动时那行「词库 6668 条」日志改成读一次就关连接）
- 行为不变：查询仍是毫秒级；每日同步跑完照旧自动换库，不用重启
- 修（审查遗留）：`_load_slang` 读的是插件包里的 `group_slang.json`，而这文件从来没随包发布过（1.5.0 审查也提过这条）；现在改读**插件数据目录**里的同名文件，属于可选私货——不放就是空字典，不再有「包里缺文件」的嫌疑

- 删掉 `search_provider` / `search_api_key`（插件不再自带搜索源，只借用 AstrBot 的网页搜索；留着只会让人以为还得自己填 key）

## 1.4.0 — 2026-10-25

**开箱即用**：内置词库随插件分发，不用先抓数据。

- 新增 `data/memes.db`（SQLite）：**6660 条**词条，含标题、标签、用法、出处，约 16MB
- 查词改走 SQLite：完整梗名精确匹配 → 包含匹配（取最长标题），单次 **0.1–3ms**
- 没有 db 时自动回退到 `index.json + details/`，再没有就回落在线 API
- 新增 `scripts/pack_data.py`：把抓取结果打包成 SQLite（「用法 / 出处」在打包时就拆好，运行时不解析 HTML）
- `scripts/sync_memes.py` 抓完自动重建 `memes.db`
- 同步/更新只补新增词条；内置库是发布时的快照

## 1.3.0 — 2026-10-25

首个公开版本。

- 本地全量字典：`index.json`（标题→slug）+ `details/*.json`，命中约 2ms
- 自动预查：裸词 / 「XX 是什么梗」等问法在 LLM 请求前注入词条内容
- 只认完整梗名（`你是什么` 不再误命中 `你是什么冠军`）
- 注入内容以「怎么用 / 怎么接」为先，要求先接梗再解释
- `/梗` 指令：图片卡片（PIL 渲染）/ 纯文字可配置
- `/黑话` 指令：新增、列表、删除（删除仅管理员），存储独立于 wiki 字典
- WebUI 扩展页面「自定义黑话」：可视化增删改
- 可选每周自动同步（内置 `scripts/sync_memes.py`，增量抓取 + 重建索引）
- 黑话文件每次保存前自动备份为 `user_terms.json.bak`
